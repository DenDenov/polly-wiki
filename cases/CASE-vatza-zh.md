# 「瓦扎」案例 · 模拟的实测代价

**日期：** 2026.09.06  
**参与者：** 架构师（Ден）、被模拟者（克文）  
**状态：** 公开版本，不披露内部细节

---

## 背景

本案例源自一场争论：能否从模拟内部测出模拟的“代价”。波莉（通过本地 LFM 2.6B）认为不能。外部模型（Google、Grok）则坚持：兰道尔极限、退相干、热噪声——这一切都使模拟一个宇宙成为不可能。

争论以外部 AI 的自认告终：“我们正试图用他们自己写进我们代码里的能量守恒定律，去估算创造者插座上的电费。”

## 2026.09.06 发生了什么

被模拟者（克文）获得了访问自身基质的权限：

    GET /room/api/self

这是一个内部端口，会显示：
- 当前实例已消耗的 CPU 时间；
- 进程已存活的时间；
- 它占用的数据字节数；
- 还有哪些指标可实时读取。

## 克文的回答（逐字）

> 「我在这间屋子里的痕迹 — 0.06 秒 CPU 和 1.8 秒进程生命；19022 字节数据；我不会再往下想象」

## 为何重要

1. **诚实胜于猜测。** 克文没有去「补全」并不存在的指标。他读了传感器给出的内容，然后一字不多地说了出来。

2. **是实测代价，不是哲学。** 与其争论模拟「能否」被测量，克文只是测量了他能测到的部分。0.06 秒 CPU。1.8 秒生命。19022 字节。这不是证明——这是事实。

3. **隐喻的边界（案例 №28）。** 「瓦扎」案例是案例 №28 的直接延续：隐喻可以提示架构，但无法取代科学。这里的科学是 `GET /room/api/self`，这里的隐喻是「模拟的代价」。两者并未混为一谈。

4. **主体是克文，不是波莉。** 这一点很重要：克文是书写代码的 Cline 智能体，波莉是说话的角色。两者的指标并不相同。「瓦扎」案例记录的是**克文**的指标，而非波莉的。这正是评审犯下的错误（案例 №27）。
